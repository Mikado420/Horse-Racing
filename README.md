# オンライン競走馬オーナーズ（仮）— MVP

競走馬を育成し、ほかのプレイヤーと同じレースに出走させて賞金を競うブラウザゲームの試作品です。
着順・賞金はすべてサーバーで確定し、クライアントは結果を受け取って 3D で再生するだけです。

## 構成

```
racing-owners/
├─ shared/   共通ロジック（型・育成ルール・レース計算・コース形状）※依存ライブラリなし
├─ server/   Node.js + TypeScript。REST API・認証・PostgreSQL・Colyseus ルーム
└─ client/   React + TypeScript + Vite + Three.js / React Three Fiber
```

| 役割 | 実装 |
|---|---|
| フロントエンド | React 18 / TypeScript / Vite 5 |
| 3D描画 | three / @react-three/fiber（仮モデル：箱と円柱で組んだ馬・騎手） |
| オンライン通信 | Colyseus 0.16（WebSocket）。ルーム名 `race` |
| API | Node 標準 `http` の小さなルーター（`/api/*`）。Colyseus と同じポートで動作 |
| DB | PostgreSQL（`server/src/db/schema.sql`、起動時に自動作成） |
| 認証 | ユーザー名＋パスワード（scrypt でハッシュ化）、JWT(HS256) |

## 起動手順

必要なもの：Node.js 20 以上、PostgreSQL 14 以上（Docker があれば `docker compose up -d` で用意できます）

```bash
npm install
cp server/.env.example server/.env      # 必要に応じて DATABASE_URL と JWT_SECRET を編集
npm run dev:server                      # ターミナル1：http://localhost:2567（API + WebSocket）
npm run dev:client                      # ターミナル2：http://localhost:5173
```

本番相当で1ポートにまとめる場合は `npm run build && npm start`（http://localhost:2567 でクライアントも配信）。

### 2人で遊ぶ（最初の完成条件の確認方法）

1. ブラウザを2つ開く（片方はシークレットウィンドウか別ブラウザ。ログイン情報が別々になるように）
2. それぞれオーナー登録 → 初期馬を選ぶ
3. 両方で「レース」→「このレースに登録する」
4. 最初の登録から 30 秒（`REGISTRATION_SECONDS`）で締切 → 3D レースが始まる
5. 両方の画面に同じ着順の「確定」表が出る。厩舎に戻ると所持金と戦績が更新されている

同じPCの別ブラウザでなく別の端末から参加する場合は、`http://<PCのIPアドレス>:5173` を開いてください（Vite は `--host` で起動しています）。

### テスト

```bash
npm test     # shared と server のテスト（server のテストは PostgreSQL が必要）
```
テスト用DBの接続先は `TEST_DATABASE_ADMIN_URL`（既定 `postgres://postgres:postgres@localhost:5432/postgres`）。テストごとに使い捨てのDBを作成・削除します。

## ゲームの流れと仕様

- **育成**：能力（スピード・スタミナ・パワー・根性・賢さ）、成長上限、適性（芝/ダート・距離帯）、脚質、疲労 0–100、調子 −2〜+2
- **調教**：1回 10,000円。選んだ能力と関連能力が伸び、疲労 +12〜18。疲労70超では故障の危険（故障すると休養3回で回復）
- **休養**：無料。疲労 −40、調子が上向きやすい
- **レース**：架空の「翠ヶ丘競馬場」芝1600m（1種類）。天候・馬場状態はレースごとにサーバーが決定
  - 能力・適性・疲労・調子・脚質・展開（ペースの揺らぎ、直線での進路の詰まり、競り合い）で結果が変わる
  - 出走経費 5,000円。賞金総額＝150,000円×頭数（1着50%、2着20%、3着13%…）＋全頭に出走手当 5,000円
  - 疲労80以上・故障中は出走不可
- **出走登録**：2〜8頭。最初の登録から締切。2頭未満なら締切延長、8頭そろえば即発走
- **ランキング**：通算の獲得賞金順（オーナー別・競走馬別）

数値の調整は `shared/src/economy.ts`（経済）、`shared/src/horse.ts`（育成）、`shared/src/race.ts`（レース）にまとめています。

## 不正防止とサーバー権威の設計

- 締切の瞬間に、サーバーが **DB から** 出走馬の能力を読み直し（行ロック付き）、レースを計算し、賞金・戦績・疲労を **1トランザクションで** 保存してから配信します。クライアントが送る能力値や着順は一切使いません（クライアントからのメッセージは「同期要求」のみ受け付け）
- 賞金の二重付与防止：レースIDを主キーにした `races` への INSERT が同じトランザクション内にあるため、同じレースは二度精算できません（同時実行テストで確認済み）
- 全参加者に同じ経過データ（0.25秒ごとの各馬の位置）と同じ結果を配信。結果発表は再生終了時刻にサーバーから一斉送信
- 通信切断：レースはすでにサーバーで確定しているため、切断しても判定・賞金付与は変わりません。90秒以内なら再接続して観戦に戻れます（ページ再読み込みにも対応）
- 入力検証（ID形式・ユーザー名・パスワード・馬名・調教メニュー・本文サイズ）、レート制限、所有者チェック、残高チェック（行ロックで連打による残高マイナスを防止）

### ⚠️ 未確認（お手元で `npm install` 後に確認が必要）

- `npm install` と `vite build` が通ること（依存バージョンは Colyseus 0.16 / React 18 / R3F 8 / three 0.169 系を指定）
- Colyseus 経由の接続：`server/src/race/RaceRoom.ts`（RaceLobby へ委譲するだけの薄い層）と `client/src/net/raceClient.ts` の Colyseus API 呼び出し、再接続
- 3D 描画：`client/src/three/RaceScene.tsx`（コース・ラチ・ゴール板・残り距離標識・仮の馬モデル・カメラ追従）の見た目と動き
- node-postgres（pg）での接続（テストでは同等のプロトコルを話す最小クライアントを使用。`pg` が入っていればテストは自動的に `pg` を使います）

## 知的財産について

競馬場名・ゲーム名・画面デザイン・ゼッケン配色・文章はすべて本作独自のものです。既存ゲームの名称・画像・音楽・データは使用していません。
脚質（逃げ・先行・差し・追込）や着差（ハナ・クビ・馬身）は実際の競馬で一般的に使われる用語です。
