## 調教師の見立ての「偏り」について（判断）

`knowledge.ts` の観測には、調教師ごとの一貫した偏り（`persistentBias`）と毎回のばらつきがあります。これは「真の能力は直接見えない」というゲームの中心となる仕組みです。調教師が見立てを外すことはあり、プレイヤー自身の分析で直していく、というものです。

- 方針：推定の仕組みそのものは残します。ただし、推定であることを常に言葉で示し、確かさが低いうちは断定させません。
  - 偏りは「見立ての癖」であり、意図的な嘘ではないためです。
  - 推定値と確かさは画面にもともと出ています。
- 廃止するもの：1回の観測値をそのまま断定的な文にする処理と、根拠のない兆候の記録です。どちらも同じ馬について週ごとに逆のことを言わせたり、起きていないことを記録したりします。
- 偏り自体もなくしたい場合は `DEFAULT_CONFIG.sources.*.biasSd` を 0 にすれば消せます。ただし既存のテスト「熟練者にも偏りがある」の前提が変わるため、別途判断が必要です。

## 実装後の仕組み（フェーズ2〜4）

### 調教師コメントの作り方（`diagnosis.ts` → `comment.ts`）
1. 記録から事実を抜き出す（`extractFacts`）
   - 記録：着順、着差、通過順位の変化、上がり3Fの順位、最後の1ハロン、ラップから見た流れ、作戦と実際の位置の違い、戦績から見た初めての距離帯や最長距離。
   - 観察：前が壁になった、外を回った、騎手が行きたがったと報告、出遅れ、ゴール前の競り合い（上位争いのときだけ）。
2. 事実から見解を判定する（`judgeViews`）
   - 見解は、根拠にした事実を必ず持つ。根拠が2つ以上なら「可能性があります」、1つなら「かもしれません」と言う。
   - 距離適性は、終盤に止まったうえで、初めての距離帯か一番長い距離だったときだけ「可能性」として挙げる。その場合も「断定できません」を添える。
   - 勝った馬に敗因めいた見解は付けない。上位でも勝ち馬から5馬身以上離されていれば「力を出せた」とは言わない。
   - どの見解にも当てはまらない負けは「原因は特定できません」とする。
3. 見解から検討事項を選ぶ（`suggest`）。効果は保証しない言い方にする。
4. 文面を作る（`composeTrainerComment`）
   - 言い回しは raceId から決める。同じ記録からは同じ文が出て、意味は変わらない。
   - 触れた事実・見解・提案を `claims` として返す。テストでは、それがすべて診断に含まれていることを確かめている。

### 情報の公開範囲
- 分析画面と結果パネルに出すもの：記録（タイム・ラップ・通過順位・上がり3F・着差・出走馬）、観察（出来事の有無だけ）、推定（根拠つき）、提案。
- 出さないもの：
  - レース中の速度（m/秒）、エネルギー残量や尽きた地点、仕掛けた地点
  - 前が詰まった秒数、外を回った距離、行きたがった秒数
  - 内部のペース指数
- 内部の値はセーブの記録には残るが、診断・分析では使わない。テストでは、内部の値だけを書き換えても診断・分析・コメントが一切変わらないことを確かめている。
- 厩舎の観察コメントは、積み上げた見立てから作る。確かさが足りないうちは「（まだ見極め中）」と添える。
- 持っていない個性の兆候は記録しない。例外は、実際に行きたがった走りの記録があるときだけ。
