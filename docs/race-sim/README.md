# レース計算 v3（脚質・ペース・スタミナの再設計）

`shared/src/owner/sim.ts`（計算）・`shared/src/owner/simTuning.ts`（展開の調整値）・`shared/src/owner/config.ts` の `race`（共通の調整値）。

## 1. 何を変えたか

| 段階 | 内容 |
|---|---|
| 1 | 脚質（位置取り）と最高速度を分けた。全馬を同じ時刻で同時に更新し、脚質ごとの目標の位置（帯）へ連続的に寄せる |
| 2 | 出走馬の顔ぶれ・枠・最初のコーナーまでの距離からペースを予測し、先頭争い・譲る・単騎逃げでペースが決まる。結果に `pace`（予測・序盤・中盤・判定・先頭争いの秒数）を残す |
| 3 | 余力が減ると徐々に速度が落ちる。先頭争い・馬群・横移動・加速・コーナー・坂・全力疾走で消耗する。仕掛けは残りの余力の見積もり（騎手の判断のずれを含む）と作戦で決まる |
| 4 | コーナーの減速、賢さによる進路選び（先読み・すき間・仕掛け前の移動）、CPU馬の能力配分の個性 |
| 5 | 記録・分析・3D観戦との連携と全体の調整 |
| 統合 | main の「着差の現実化」（v2.1、`docs/margins`）を取り込んだ（下の 2 章） |

3D観戦は計算結果（位置・進路の記録）をそのまま再生するだけで、着順とタイムは計算結果だけが基準。乱数は `createRng`（シード付き）だけを使う。

## 2. v2.1（着差の現実化）との統合

main で先に入った v2.1 の考え方を、v3 の計算の中に取り込んだ。

| v2.1 の要素 | v3 での扱い |
|---|---|
| 馬ごとの差を縮める `differenceScale`（0.5） | そのまま使う（能力値・適性・状態・その日の出来）。スタミナの「余力の量」にも同じく効く |
| 最高速度・状態・芝ダートの係数（`topBase` など） | そのまま使う |
| 有酸素で賄える消耗 `aerobicRate`（7.9） | そのまま使う。さらにスタミナが有酸素の量にも効く（`tuning.aerobicStamina`=0.9）。長い距離ほどスタミナの差が出る |
| 距離に応じた道中のペース `cruisePerKm`（0.05） | 自分のリズムの巡航に掛ける。ペース指数の基準も同じだけずらすので、距離によって判定が偏らない |
| 出遅れの縮小 `startDelayScale`（0.5） | そのまま使う（分析の出遅れの基準 0.175秒と合う） |
| `fadeReserve`・`emptyFloor` | v3 の「徐々に落ちる失速」の始まりと下限として使う（0.18・0.86。v3 用の値） |
| `formSd`・`energyScale` | v3 用の値（0.011・0.9） |
| `followRange`・`followMaxFraction`・`staminaPacing`・`followOverPace`・`duelTaper` | v2.1 の仕組み。v3 では流れへの追従・競り合い・仕掛けの判断が同じ役割を受け持つので使わない |

`race.engine` で計算の版を選ぶ。`withConfig({ race: RACE_V21 })` で v2.1、`withConfig({ race: LEGACY_RACE_V20 })` で v2.0 の結果を、同じ出走馬・同じシードからそのまま再現できる（`simLegacy.ts`。テストで基準値と照合）。

CPU馬の能力配分を第4段階で変えたため、過去の基準値の照合には当時の CPU 馬の生成で作った出走馬（`shared/test/fixtures/cpu-entries-v21.json`）を使う。

## 3. 結果（CPU馬8頭立て）

### 着差（`scripts/margin-stats.ts`、シード組1〜3・各6,192レース、`margins-v3-123.json`）

| 条件 | 着差中央値（馬身） | 90%点 | 大差 | 1-2着（時計比） | 能力1位の勝率 | エネルギー切れ |
|---|---|---|---|---|---|---|
| 全体 | 1.87（v2.1 1.43） | 6.04（5.07） | 1.6%（1.6%） | 0.392%（0.337%） | 26%（26.5%） | 3.4%（0.6%） |
| 短距離 | 1.66 | 5.4 | 1% | 0.492% | 24.9% | 0.2% |
| マイル | 1.86 | 5.92 | 1% | 0.37% | 26.4% | 1% |
| 中距離 | 2.01 | 6.15 | 1.3% | 0.321% | 26.3% | 5.5% |
| 長距離 | 2.48 | 8.22 | 5.7% | 0.293% | 28.2% | 15.2% |

1-2着の差（英国の重賞の研究で平均 0.32%）は現実的な範囲。v2.1 より少し広いのは、脚質・ペース・仕掛けの違いで着差がつくため。
長距離のエネルギー切れには距離が長すぎる馬が含まれる（距離が合う馬に限ると `margins.test.ts` の基準 5% 未満）。

### 展開（800レース、番組表のコースと馬場）

| 脚質 | 序盤 → 残り400m → 着順の平均位置（0=先頭） | 勝率 |
|---|---|---|
| 逃げ | 0.26 → 0.40 → 0.46 | 16.1% |
| 先行 | 0.41 → 0.44 → 0.46 | 14.7% |
| 差し | 0.62 → 0.56 → 0.53 | 9.5% |
| 追込 | 0.74 → 0.62 → 0.55 | 9.4% |

- ペースの判定：スロー 206・平均 294・ハイ 300。逃げ馬の勝率はスロー 19.8% → ハイ 14.6%、追込はスロー 11.0% → ハイ 10.9%
- 仕掛けの作戦：早め 勝率17.7%（失速32.3%）・普通 12.5%（11.3%）・遅め 7.3%（9.2%）
- 上がり3F：中央 33.9秒（10%点 32.6・90%点 35.7）

## 4. 分析との関係

分析（`report.ts`）のペースは、誰でも確かめられる先頭のラップから判断する。v3 で道中の運び方が変わったため、判定の基準（距離帯ごとの15%点・85%点）を main と同じ方法（4年分の番組 1,292レース）で計算し直した。
計算内部のペース指数（`pace`）は記録に残すが、分析の文章の根拠にはしない（分析の再設計の方針：記録と推定を分ける）。

## 5. 互換性

- セーブの形式は変えていない。古いセーブはそのまま読める（調教師のコメントは main の方針どおり読み込み時に記録から作り直す）
- 過去のレース記録は再計算しない。新しい項目（`pace`・`reserve` など）は新しいレースにだけ付く

## 6. 残っている課題

- 遅めの仕掛けの勝率が低い（7.3%）。早めの仕掛けは失速が多いが、それでも勝率が高い
- 賢さによる「前が詰まりにくさ」の効果は小さく、調整値を少し変えると逆転することがある（テストは通っている）
- 短距離では前半がゆったりで後半が速いラップになりやすい（実際の短距離は前半が速いことが多い）
